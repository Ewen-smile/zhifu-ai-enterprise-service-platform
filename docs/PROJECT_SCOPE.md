# 产品范围与功能实现状态（V4.0）

**产品定位**：虚构企业场景下的双角色 IT 智能服务平台，面向 AI 产品经理作品集展示。功能已用于本地 MVP 测试，但未达到企业生产部署标准。

## 九张页面

| 页面 | 本地演示实现 | 关键限制 |
|---|---|---|
| 员工首页 | 快捷入口、常见指南、最近工单 | 数据来自同一演示数据库 |
| AI 智能问答 | 本地检索或 Dify Chatbot / Chatflow；支持转工单 | Dify 模型、RAG 和分类规则由外部应用决定 |
| 我的工单 | 列表、筛选、查看详情 | 未登录，全部工单属于同一演示空间 |
| 提交工单 | 标题、描述、类别、优先级；可由问答预填 | 表单未连接真实组织 / 审批系统 |
| 自助知识中心 | 检索、分类、阅读指南 | 无真实用户或访问权限区分 |
| 管理总览 | 工单数量、状态、趋势与知识统计 | 不展示未接入的 AI 命中率、满意度等数据 |
| 工单工作台 | 筛选、分配、状态更新、重新打开 | 无真实分派通知、SLA、审计日志 |
| 知识库管理 | 本地知识检索、详情、Dify 重试同步 | 只提交文本，Dify 异步建索引；非双向同步 |
| 新增知识条目 | 新增标题、分类、关键词、正文 | 附件无法上传；浏览器草稿为 sessionStorage |

## 实际 API（摘自最终版 app.py）

- `GET /api/health`：本地/Dify 模式与知识同步配置状态
- `GET /api/summary`：工单及知识数量统计
- `GET /api/tickets`、`POST /api/tickets`、`PATCH /api/tickets/{id}`：工单查询、新建、状态更新
- `GET /api/knowledge`、`POST /api/knowledge`、`POST /api/knowledge/{id}/sync`：知识查询、新建、Dify 文本提交
- `POST /api/chat`：问答；根据环境变量选择本地知识检索或 Dify 应用接口

## 当前版本功能限制

- 无账号注册、员工登录、角色权限控制及真实企业组织关系；两个工作空间不做安全隔离。
- 无知识附件上传、正式审批流、通知系统、工单 SLA、真实满意度测量与审计日志。
- 未记录完整 Dify Retrieval 节点内容；不能把分类准确率当作知识库召回率。
- 没有提供 Dify Chatflow 的 DSL 导出，需在自己的 Dify 中配置模型和检索流程。
- 前端有部分模型答复的 Markdown / 内部分类标记清理；但不能保证外部模型永不产生不当输出。
- 数据库中的原始种子条目保留历史类别 `软件应用`、`安全规范`；可见的五分类为 `办公网络`、`账号权限`、`办公软件`、`办公设备`、`其他问题`，并非所有历史知识自动归一化。
